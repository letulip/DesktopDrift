## Что делает фича
В SVG трассы есть прокси-линия `ITEM_COLA_CAP`. Крышка собирается, когда машина **обводит её дрифтом 2 полных круга** (`CAP_LOOPS=2`), идёт радиальная заливка прогресса (wedge-clip арка), при сборе **+500 очков**; собранные крышки **персистятся и восстанавливаются при старте**; бейджи `N/M` на index.html и tracks.html. Pure-математика углов вынесена в `js/cola.js` и покрыта юнит-тестами.

## 🔑 Главное: персист крышек — **по ИНДЕКСУ** (латентная мина)

Фактическое состояние на HEAD: собранная крышка ключуется по **порядковому индексу** в массиве `T.collectibles[]`, не по стабильному id.
- Запись: `game-engine.js:114` → `capCollect(T.id ?? '', i)`, `i` — индекс из `collectibles.forEach`.
- Хранилище: `store.js:43-58` — `stats.caps[trackId] = number[]` (массив индексов). **Изоляция по `trackId` есть** — коллизий между трассами нет (противоречие коммитов `c35b0ac`/`df65447` разрешено в пользу keyed-by-trackId + массив индексов).
- Восстановление: `game-engine.js:60-64` → `collected: _prevCollected.has(i)`.

**Почему мина:** массив `collectibles[]` строится в порядке обхода DOM `querySelectorAll('line[id^="ITEM_"]')`. Если автор позже **добавит / переставит / удалит** крышку в SVG — порядок сдвинется, и сохранённый индекс `0` укажет на другую крышку (или на удалённую) → игрок видит собранной не ту крышку / теряет прогресс. **Сейчас по 1 крышке на трассу (`caps:1`), поэтому сдвиг невозможен — дефект латентный, не активный.** Но фича и скилл `desktopdrift-new-track` явно нацелены на рост числа крышек.

**Как чинить (пока крышка одна и сейвов с >1 ещё нет — идеальный момент):** ключевать стабильным id. У всех строк `el.id` одинаков (`ITEM_COLA_CAP`), поэтому нужен либо суффикс в SVG (`ITEM_COLA_CAP_1/_2/...` → `capId = rawId`), либо координатный ключ `capId = \`${Math.round(x)},${Math.round(y)}\``. Затем `capCollect(trackId, cap.capId)` и `collected: prev.has(cap.capId)`. Координатный ключ переживает перестановку/вставку, ломается только при сдвиге самой крышки (что логично — это уже другая крышка).

## 🔋 Батарея / per-frame стоимость — **низкая, приемлемая**

`render.js:231-290` (`drawCaps`):
- Крышек на трассе сейчас **1** → цикл O(1).
- `clip()` (wedge-арка) строится **только при `progress>0`** (`render.js:268`) — для несобранной без активного sweep и для собранной (`progress=0`) клип пропущен. Работает лишь короткими интервалами активной заливки.
- `shadowBlur=12` — только в pop-burst (`pop=0.6с` после сбора, сразу затухает в 0), не per-frame-постоянно.
- save/restore сбалансированы, утечек контекста нет.

**Вывод:** при 1 крышке фича батарею не двигает. **При масштабировании до N крышек** добавить frustum-culling (скип крышек за вьюпортом) — сейчас рисуются все.

## ✅ Store-схема и миграция — **сделано правильно, релиз НЕ сотрёт данные**

- `VERSION` остался **`1`** (`store.js:7`) — намеренно: новое поле `caps` живёт в `stats`-слайсе, который **lazy-инициализируется** (`store.js:43`: `if(!_s.stats) _s.stats={}`), а не в `defaults()`. Старый сейв `version:1` без `stats` проходит проверку `raw.version===VERSION`, грузится как есть, `stats()/collectedCaps()` доинициализируют пустоту на лету. **Records / garage / achievements целы.**
- Гард на отсутствие `caps`: `collectedCaps` → `st.caps[trackId] ?? []` (`store.js:49`). Безопасно.
- *(Это правильный обход проблемы S1/S2 из основного отчёта — добавили бы `caps` в `defaults()` + bump VERSION без миграции → сброс всего. Авторы этого избежали.)*
